# 20XX on the Wii

How the port runs [20XX Hack Pack](https://github.com/DRGN-DRC/20XX-HACK-PACK) from its own disc
image, and how it offers part of 20XX's menu in the plain game and in Slippi Online. For players:
[the README](../README.md#20xx).

Everything here was read from, and tested with, a 20XX 5.0.2 image (MD5
`d926ba5b39551f5245fd655bc1dfeb3f`). Other versions are unproven.

## A mod on its own disc image

`wii/src/launcher/mods.c` lists the images that are Melee 1.02 (`GALE01`, revision 2) but whose
executable header or disc name is not the original's. One whose disc name or path contains "20XX"
is listed as **20XX**, any other as **Modded Melee**. A mod starts without Slippi and keeps its own
saves (`card20xx/`, `cardmod/`).

- **The executable.** The port loads the image's `Start.dol` over the game's and puts its own
  changes back on top: its branches to the SDK functions it replaces, except where the mod has code
  of its own (20XX puts code in THPDec's and MCC's functions, and in Tournament mode's). A mod's
  other changes to those SDK functions are left out, as Gecko codes' are.
- **The GameCube's memory layout.** 20XX branches to fixed addresses inside the files it loads (its
  character select's code is in `MnSlChr.0sd`, at the address a GameCube gives that file), reads the
  SDK's file table itself (`FstStart`, which the port fills in from the image's), and calls
  `__flush_cache` after loading code. So the game's arena starts where a GameCube's does (the end
  of the main stack, 0x804EEC00), and the port's own MEM1 data is at the top of MEM1. 20XX also
  reads the SDK's `__OSArenaHi` itself, so the port keeps the SDK's two arena variables as its own
  are.
- **Widescreen.** The launcher's Screen setting turns on 20XX's own widescreen (a value of its
  debug menu, set once the game has loaded its save); 20XX's menu can still turn it off.
- **Lag reduction.** 20XX's "Are you using HDMI?" paces the game by the controllers' polls instead
  of the retrace: it registers a polling callback (`SIRegisterPollingHandler`, `wii/src/pad.c`)
  that wakes the main loop at the frame's second poll, and puts a step of its own in the
  GameCube's retrace handler. The port's retrace (`wii/src/vi.c`) does that step and that wake-up.

## 20XX's menu in Melee and Slippi Online

The launcher's **20XX menu** setting (`xx_menu=`, off by default, shown only with a 20XX image)
offers the part of 20XX's debug menu that changes only sound or picture. Everything else in that
menu changes the game's state or what one player knows, and an opponent on plain Slippi must be
playing the same match.

### Rules

1. **Nothing of 20XX's is in this repository or in a release.** Labels, song names, songs, stage
   and costume files and defaults come from the player's own image as the game starts.
2. **None of 20XX's code runs.** Where 20XX patches the game, the port gives the game another file
   (or other bytes of a file) as it looks one up. The menu is the game's own debug menu code.
3. **Off means absent.** With the setting off, or no 20XX image, no file is opened and no memory
   taken; the calls the port takes over (`cmake/Wii.cmake`'s `--redirect` lines) go straight to
   the game's own functions.
4. **An item exists only if the port acts on its variable.** 20XX's options are words in its
   executable's data; the port has its own word for each one it implements
   (`melee_wii_mod_value`), and an item without one is not copied.
5. **Nothing touches what a match depends on.** A random song or look comes from the port's own
   generator, never the game's.
6. **Values are fixed during a match.** The menu opens only from the main menu.
7. **No MEM1.** The lists, names and values are in MEM2; the game's arena is never shrunk.

An image is refused (in the log only) if it has no `MnSlChr.0sd`, if its executable's song names
and playlists are not where 5.0.2 has them, or if a default is out of range.

### Parts

| File | What it does |
|---|---|
| `wii/src/dvd.c` | The 20XX image as a second image: its files have entry numbers after the game's. A substitute function is asked at each lookup; another is called with what each read brought |
| `wii/src/mod_values.c` | Opens the image, reads 20XX's defaults from its executable, holds the player's values (`sd:/apps/melee/20xx.ini`; its keys are listed in the file) |
| `wii/src/mod_menu.c` | The menu: the copy of 20XX's lists, the callbacks, Y on the main menu, Extra on Slippi's Online Play screen |
| `wii/src/mod_songs.c` | The playlists: which song file the game gets; music off, second songs off |
| `wii/src/mod_stages.c` | Looks and costumes: which file the game gets, the verdicts (`sd:/apps/melee/20xx-stages.txt`), the original's song rows and Final Destination's colour put over what is read |
| `wii/src/mod_fighters.c` | Shield colours; the character select window's colours for a 20XX costume |
| `wii/src/stage_check.c` | Is a file the original with another look? |
| `wii/tools/mod_menu.py` | Lists 20XX's menu from an image, on a PC: `mod_menu.py 20XX.iso [--outline]` |
| `wii/tools/stage_check.py` | The same comparison on a PC, saying what differs (the C one's reference): `stage_check.py [-v] ORIGINAL MODDED...` |

### The menu

20XX's menu is the game's own debug menu with other lists, and the debug menu's code and scene are
still in the retail game.

- As the game starts, the port copies the lists it offers out of the image's `MnSlChr.0sd` into
  MEM2: an item is kept when the port has its variable, a submenu when something in it is kept.
  Values point at the port's words; every callback is the port's.
- Y on the main menu leaves for the game's debug mode as a menu entry leaves for its mode. That
  scene opens its menu with a call the port takes over, which gives it the port's list. Slippi's
  codeset patches neither place.
- The debug menu reads the stick; the D-pad is added. A opens or plays, B goes up a level and
  leaves from the top, Start leaves from anywhere. Leaving saves the values and returns to the
  screen the menu was opened from.
- A song is played with A only; going through the songs changes the value and leaves what is
  playing.
- **Extra** on Slippi's Online Play screen takes the place after Party (Log-out's, which Slippi
  always locks). Its label is put together from letters of the game's own menu labels, in Slippi's
  menu file as it is kept in RAM; nothing is drawn by the port.

### Music

20XX's playlist code patches the game's music function and picks random songs with the game's own
`HSD_Randi`, which both sides of an online match must draw from alike. The port does neither.

- The game's 99 song names are at the same addresses in both executables: where the original has
  `ystory.hps`, 20XX has `27.hps`, its number for that song. A song 20XX left its name (fanfares,
  the hammer's) has no number and is never replaced.
- When the game looks a numbered song up, the playlist that applies picks one, and the game gets
  `audio/XX.hps` of the 20XX image. The pick is kept for the scene: the game asks again in a match
  (after the hammer's song, or as a rollback plays a frame again) and must get the same one.
- The global playlist replaces the stages' and menus' songs only. The menu playlist replaces both
  of the game's menu songs.
- **Disable all music:** the call that starts a song is taken over; the song is not started.
- **Disable alternate music:** a stage's second song, when the game draws it (from its own random
  numbers, as the opponent's game does), is given the first song's file. By name alone a second
  song can't be told from another stage's first, so this goes by the loaded stage's rows.
- The music stream is outside the savestates already (see [netplay.md](netplay.md)).

### Stage looks and the check

A look is a whole stage file (`GrNBa.3at` is Battlefield's third). The game gets it when it looks
its own file up, **if it passed the check**: 20XX's files differ in more than textures (its default
Battlefield has wider collision bounds; others move joints, change item data or have other models).

The check walks both files together by their structures.

- **Must be equal:** the collision, the stage's parameters, every joint's place in its tree and its
  position, rotation and scale, the joint animations, the splines, the cameras, the stage's own
  items, the particles' programs (they draw from the game's random numbers), and anything whose
  structure isn't known.
- **Free to differ:** a joint's display objects (meshes, materials, textures) and render-pass
  flags, material and shape animations, lights, fog, shadows, particle textures.
- A file more than 256 KB bigger than the original is refused (the stage's memory is the game's).

For 5.0.2, 49 of 75 looks pass: Battlefield 1–5; Final Destination 1–6, 8, 9, 12; Yoshi's Story
1–8, 11, 12; Fountain of Dreams 1–7, 9, 12; Dream Land 1–4, 7–11; Pokémon Stadium 1–5, 7, 8.

20XX gives some looks their own songs, as numbers the original game doesn't have. The check
returns the original's rows, and the port puts them over the file's as it is read. Final
Destination's custom colour is written the same way (two materials' colours, at fixed places of a
file of the original's size).

The first start with the setting on checks the image's stage and costume files (about 40 s, with a
progress bar) and keeps the verdicts for that image in `20xx-stages.txt`; deleting the file checks
again.

### Shield colours

A shield has the colour of its port: a table of four colours in the fighters' common data
(`PlCo.dat`). 20XX writes its menu's colours there as the game loads the file for a match; so does
the port, and it puts the game's own back for a player whose colour is off. Online, the first
colour is this console's player's, whichever port Slippi gives it.

### Costumes

20XX has up to two more files for each costume (`PlFxNr.lat` and `PlFxNr.rat` for `PlFxNr.dat`).

- **L and R on the character select screen** (the game's and Slippi's, which is the same code)
  give a character its costume's first or second other file; the same button again, its own.
- **The choice is the costume's, not the player's,** as in 20XX, and lasts until the game is left:
  whoever next plays that character in that costume on this console is shown the same file. It is
  only what this console draws.
- **The game gets the file** if it passed the same check as the stages': a costume file holds the
  character's skeleton, which the hitboxes hang on. Of 5.0.2's 254 files, 242 pass; for the others
  the button says no.
- **The portraits are 20XX's** while its costumes are on: 118 pictures with their palettes, one
  stretch at the same place in 20XX's `MnSlChr.0sd` and the game's `MnSlChr.usd`. The game reads
  that stretch from 20XX's file and nothing else of it.
- **The player's window** takes two colours of the costume's own while an L or R costume is chosen
  (a table in 20XX's `MnSlChr.0sd`), with 20XX's sound.

### Not offered, and why

| Option | Why not |
|---|---|
| Disable FD BG transitions, BF rainbow water BG | Both backgrounds draw from the game's random numbers; 20XX's patches change how many are drawn |
| Rainbow FD | Writes at an address worked out from 20XX's own memory layout |
| Disable in-game GFX and textures | The game's effects draw from the game's random numbers |
| Custom metal colours | For 20XX's own "metal" characters, which the plain game doesn't have |
| The HUD options | Each is a patch in the HUD's code, to be redone one by one. Not done |
| Hitbox display, L-cancel, wavedash and action-state flashes | They show what the opponent doesn't see |
| 26 of the 75 stage looks, 12 of the 254 costumes | They fail the check |
| Everything else (stage hazards, rules, characters, items, mechanics, game modes, CPUs, training codes, SD Remix) | It changes the game's state |

### Tested

On a Wii against Slippi Dolphin, with the replays of both sides compared frame by frame (as of
2026-11-09): 17 games, identical on every frame, with random looks and random songs from the
global playlist (Battlefield looks 1, 2 and 4, Final Destination 5, Fountain of Dreams 4 and 7,
Dream Land 2, 3 and 4, Pokémon Stadium 4 and 5).

Not yet proven in a match against a PC: Yoshi's Story's looks, the looks not drawn in those games,
Final Destination's custom colour, the shield colours and the costumes.

### Reference

- 20XX's menu file: `MnSlChr.0sd`, loaded by 20XX at 0x80BEC720; 82 lists, 1,851 items of 32 bytes.
- 20XX's variables (1.02): playlists' owners 0x803FA8E0, types 0x803FA940, songs 0x803FA9B0 (0x60
  a playlist), global 0x803FAE94, affects menu 0x803FA17C, preview 0x803FA3CC; looks
  0x803FA1D4–0x803FA1E8; Final Destination's colour 0x803FA398–0x803FA3A4.
- The game's song names: 0x803BBDDC–0x803BC314.
